# Mobile reader app (Tauri 2)

A reader-only companion app: discover published stories, read, sync progress,
Continue Reading shelf. Writing stays on the web. iOS first; nothing on the
TypeScript side is iOS-specific, so Android is a later `tauri android init`.

## Shape

It is a **second Vite entry over the same `src/`**, not a separate project.

| Piece | Where |
|---|---|
| Entry HTML | `mobile.html` |
| Vite config | `vite.mobile.config.ts` (aliases and dev proxy come from `vite.config.ts`) |
| Shell, router, screens | `src/mobile/` |
| Native shell | `src-tauri/` |
| Browser test | `cypress/mobile/`, `cypress.mobile.config.mjs` |

The web entry (`src/main.tsx`) never imports `src/mobile/`, so the web bundle
does not change.

What the app reuses unchanged: `AllStories`, `StoryDetail` and the whole reader
under `routes/Story/components/reader/`, the story-data client, `platform-auth`,
the query hooks, the stores and the Inkwell tokens.

Rules worth knowing before changing it:

- **Route paths match the web app.** `StoryDetail` matches
  `/story/:id/read/:chapterId?` itself and shared components build links with
  `lib/seoPaths.ts`. The router is a hash router because a bundled app has no
  server to rewrite deep paths.
- **Unknown paths open the website.** `routes/ExternalLink.tsx` is the `*`
  route, so a link to a profile or the studio inside a shared component works
  without that component knowing about the app.
- **The page scrolls in `main[data-app-scroll]`**, the same contract as
  `NavbarWrapper`. The reader's scroll tracking and the discovery grid's
  infinite scroll depend on it.
- **`VITE_PLATFORM === "mobile"`** is defined only by the mobile config. It
  turns read-aloud off (`config/featureFlags.ts`).
- **Accounts:** sign-in only, plus guest reading. Sign-up is invite and magic
  link, which stays on the web.
- A production build requires an absolute https `VITE_STORY_DATA_URL` and fails
  without one.
- **Auth is created with `initializeAuth`, not `getAuth`, on the mobile build**
  (`packages/platform-auth/src/firebase.ts`). `getAuth` installs the
  popup/redirect resolver, which never finishes starting inside the Tauri
  webview: `onAuthStateChanged` never fires, `useAuthIdentity().loading` stays
  true, and the reader sits on its skeleton forever. A browser does not
  reproduce this, so `yarn cy:mobile` cannot catch a regression here.

## Commands

```bash
yarn mobile:dev     # the app in a browser at http://localhost:5174/mobile.html
yarn mobile:build   # typecheck + bundle into dist-mobile/
yarn cy:mobile      # browser test; needs mobile:dev and ./dev-new.sh running
yarn tauri dev      # desktop window, quickest way to see the native shell
yarn ios:dev        # iOS Simulator (see prerequisites)
yarn ios:build
```

`yarn cy:mobile` uses its own Cypress config on purpose. The main suite's
support file resets the Auth and Firestore emulators before every test; never
point it at the mobile spec against a dev stack you want to keep.

## iOS prerequisites (one-time)

Xcode (selected with `xcode-select`), CocoaPods and XcodeGen
(`brew install cocoapods xcodegen`), and the Rust targets
`aarch64-apple-ios` and `aarch64-apple-ios-sim`.

`src-tauri/gen/apple` is generated by `npm run tauri -- ios init`. Always run
it through a package-manager script: the Xcode build phase records how the CLI
was invoked, and a project generated by calling `node_modules/.bin/tauri`
directly fails with "Cannot find module .../gen/apple/tauri".

Do not add `tauri-plugin-log` back. It pulls in `num_threads`, which does not
compile for iOS against the current `libc`.

Develop in the **Simulator** against `./dev-new.sh`: it shares the host network,
so the emulator addresses hardcoded to `127.0.0.1` in `platform-auth` and
`cloudFunctions` work. A physical phone cannot reach those; test it against
production config with `VITE_USE_EMULATORS=false`.

## Dependency review exception

`src-tauri/Cargo.lock` includes `glib 0.18.5` through Tauri's Linux GTK3
dependencies, even though the reader ships on iOS. Cargo lockfiles include
dependencies for other targets; `glib` is absent from the iOS build graph.

Dependency review allows only
[GHSA-wrw7-89jp-8q8g](https://github.com/advisories/GHSA-wrw7-89jp-8q8g)
(RUSTSEC-2024-0429), the `VariantStrIter` unsoundness advisory. Its fix is in
`glib >=0.20`, which cannot replace `0.18` in Tauri's GTK3 stack. Tauri 2.12.3
[tracks the same exception upstream](https://github.com/tauri-apps/tauri/blob/tauri-v2.12.3/.cargo/audit.toml).
This exception does not patch the Linux dependency. Reassess it before shipping
a Linux build, and remove `allow-ghsas` from `.github/workflows/security.yml`
when Tauri's GTK4 migration provides a compatible patched dependency.

Verify the iOS target graph with:

```bash
cargo tree --manifest-path src-tauri/Cargo.toml --locked --target aarch64-apple-ios -i glib
```

Cargo should report nothing to print. All other advisories remain blocking.

## Not done yet

- **iOS coverage so far:** the app builds, launches in the iPhone Simulator
  against the dev server, loads stories, resolves the initial auth state and
  respects the safe areas. Sign-in and session persistence in WKWebView have
  not been exercised there, and a
  bundled (non-dev-server) build has not been run, so story-data accepting the
  app origin is still an assumption.
- **CORS.** A bundled app calls story-data from `tauri://localhost` (iOS) and
  `http://tauri.localhost` (Android). Both need adding to `cors_origins` in
  `story-data/terraform/variables.tf`, and to `CORS_EXTRA_ORIGINS` for the
  recommendations Function.
- **CSP** is unset in `src-tauri/tauri.conf.json`; set it once the production
  story-data host is fixed.
- **Bundle identifier** is `com.thetaletribe.reader`. Confirm it before the
  first App Store upload; it cannot be changed afterwards.
- App icon and splash are the Tauri placeholders.
- Offline states, swipe between chapters, status-bar styling.
